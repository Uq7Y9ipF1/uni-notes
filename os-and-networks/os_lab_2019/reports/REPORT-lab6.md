# Отчёт: Лабораторная работа №6 — Сокеты TCP, распределённое вычисление факториала

## ТЗ (что нужно было сделать по сути)
1. Дописать `client.c` и `server.c` — клиент-серверное приложение поверх **TCP**, которое распределяет вычисление `k! % mod` между несколькими серверами:
   - клиент получает аргументы `k`, `mod`, путь до файла со списком серверов (`ip:port`, по одному на строку); режет диапазон `[1..k]` на куски и отправляет каждому серверу его «кусок вычислений» и `mod`;
   - сервер принимает `(begin, end, mod)` как три uint64, считает произведение диапазона **в несколько потоков** (`--tnum`) и возвращает один uint64 — результат куска;
   - в исходной заготовке клиент опрашивал сервера последовательно — требовалось распараллелить работу с серверами и объяснить выбранный способ.
2. Создать makefile для клиента и сервера.
3. Найти дублирующийся код в client/server и вынести его в библиотеку; обновить makefile.
4* (опционально). Доступ из внешнего мира (проброс порта в Codenvy).

## Как реализовано

### Сервер (`server.c`)
Аргументы: `--port 20001 --tnum 4` (с валидацией диапазонов). Цикл:
```
socket -> setsockopt(SO_REUSEADDR) -> bind(INADDR_ANY:port) -> listen(128)
  -> accept()            ждём подключение
     -> цикл по соединению:
        recv 3*uint64 (begin,end,mod)
        диапазон [begin,end] делится на tnum частей;
        каждая часть считается своим pthread'ом (Factorial + MultModulo);
        частичные результаты перемножаются под мьютексом/после join;
        send 1*uint64 обратно
```
Сервер обрабатывает несколько запросов в одном соединении и готов к следующему клиенту после закрытия текущего.

### Клиент (`client.c`) — задание 1 и распараллеливание
Аргументы: `./client <k> <mod> <servers_file>`.
1. Читает список серверов `ip:port` из файла (пропускаются пустые строки и комментарии `#`).
2. Режет `[1..k]` на N равных кусков по числу серверов (последнему — остаток до k).
3. **Распараллеливание:** на каждый сервер заводится отдельный **поток pthread**: внутри потока — свой `connect/send/recv`. Частичные произведения складываются в общую переменную `g_total` через `MultModulo` **под мьютексом**; ошибки серверов считаются тоже под мьютексом. Главный поток делает `pthread_join` со всеми и печатает `answer:`.

Обоснование выбора: это минимальное по коду решение, не требующее неблокирующего I/O, select/poll или дополнительных процессов; все сервера гарантированно считают свои куски одновременно, а мьютекс защищает единственную точку записи общего результата (см. гонку из лабы 5).

### Задания 2–3 — makefile и общая библиотека
Дублировавшиеся в client.c и server.c функции `MultModulo` и `ConvertStringToUI64` вынесены в `common.c/common.h`, из которых собирается статическая библиотека `libcommon.a` (задание 3). Makefile:
```makefile
all: client server
libcommon.a : common.o ; ar rcs libcommon.a common.o
client : client.c libcommon.a ; gcc ... -lpthread
server : server.c libcommon.a ; gcc ... -lpthread
clean  : rm -f client server common.o libcommon.a
```

## Проверка (фактический прогон)
Запущены два сервера (порты 20001 и 20002, по 4 потока каждый), файл `servers.txt`:
```
127.0.0.1:20001
127.0.0.1:20002
```
```
$ ./client 40 998244353 servers.txt
Server 127.0.0.1:20002 piece [21, 40] => 41700312
Server 127.0.0.1:20001 piece [1, 20] => 401576539
answer: 504900914

$ python3 -c "import math; print(math.factorial(40)%998244353)"
504900914        # совпадает ✔
```
Куски обработаны двумя серверами параллельно, ответ корректен. Бинарные артефакты сборки в git не коммитятся (задание «перед сдачей»).
