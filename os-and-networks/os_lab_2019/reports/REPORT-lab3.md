# Отчёт: Лабораторная работа №3 — Процессы, fork, pipe, Makefile

## ТЗ (что нужно было сделать по сути)
1. Реализовать `GetMinMax(int *array, unsigned int begin, unsigned int end)` — поиск минимума и максимума на полуоткрытом отрезке `[begin, end)` массива (`lab3/src/find_min_max.c`).
2. Написать `parallel_min_max.c`: распараллелить поиск min/max по всему массиву между **дочерними процессами** (`fork`), каждый обрабатывает свой кусок; результаты передаются родителю **через временные файлы** (`--by_files`, задание 2).
3. Тот же параллельный поиск, но обмен результатами **через анонимные каналы `pipe`** (задание 3). Разобраться с клонированием файловых дескрипторов при fork и необходимостью закрывать «чужие» концы каналов.
4. Научиться пользоваться `make`: дописать в makefile таргет `all`, чтобы одной командой собирались все программы (задание 4).
5. Изучить семейство `exec`: написать программу, которая создаёт дочерний процесс и **заменяет** его образ на уже готовую программу `sequential_min_max` (задание 5).

## Как реализовано

### Задание 1 — GetMinMax
```c
struct MinMax GetMinMax(int *array, unsigned int begin, unsigned int end) {
  struct MinMax min_max;
  min_max.min = INT_MAX;   // безопасные стартовые значения
  min_max.max = INT_MIN;
  for (unsigned int i = begin; i < end; i++) {
    if (array[i] < min_max.min) min_max.min = array[i];
    if (array[i] > min_max.max) min_max.max = array[i];
  }
  return min_max;
}
```
Сложность O(end−begin). Глобальный ответ = min из всех локальных min и max из всех локальных max (ассоциативность операции → корректное распараллеливание).

### Задания 2–3 — parallel_min_max.c
Общая схема:
- разбор аргументов через `getopt_long`: `--seed`, `--array_size`, `--pnum`, флаг `--by_files` (`-f`);
- генерация массива `GenerateArray(array, size, seed)`;
- `pnum` вызовов `fork()`. Ребёнок номер `i` считает отрезок `[i*chunk, (i+1)*chunk)` (последний — до конца массива) и возвращает результат родителю:
  - **файловый вариант:** пишет `"min max"` в `tmp_i.txt`; родитель после `wait()` читает и удаляет файлы;
  - **pipe-вариант:** до fork создаётся `pnum` каналов `pipe(pipes[i])`; ребёнок закрывает читающий конец `pipes[i][0]` и пишет бинарно `write(pipes[i][1], &min_max, sizeof(struct MinMax))`. Родитель закрывает все пишущие концы и по очереди `read()` с каждого канала — чтение блокируется до записи/закрытия, синхронизация бесплатна;
- замер времени `gettimeofday` до и после, вывод `Min / Max / Elapsed time`.

Важные детали:
- общий массив копируется детям копированием страниц (copy-on-write) — дублирования памяти нет до первой записи;
- если `fork` вернёт −1 — печать ошибки и выход;
- все дети дожидается `wait()`, иначе остались бы зомби.

### Задание 4 — makefile
Добавлен таргет `all`, зависящий от `sequential_min_max`, `parallel_min_max` и `exec_seq`; объектные файлы `utils.o`, `find_min_max.o` компилируются отдельно (`-c`) и переиспользуются; добавлена цель `clean`. Теперь достаточно `make`.

### Задание 5 — exec_seq.c
```c
pid_t pid = fork();
if (pid == 0) {                       // ребёнок
  char *args[] = {"./sequential_min_max", "42", "100000", NULL};
  execvp(args[0], args);              // заменяет образ процесса новой программой
  perror("execvp failed");            // сюда доходим только при ошибке
  return 1;
} else {                              // родитель
  int status; waitpid(pid, &status, 0);
  printf("Child process finished with status %d\n", WEXITSTATUS(status));
}
```
`fork` порождает точную копию, а `execvp` поверх этой копии загружает исполняемый файл `sequential_min_max` (поиск по `PATH`/относительный путь + массив аргументов). Код после `execvp` выполняется только если замена не удалась.

## Проверка (фактические запуски)
```
$ ./sequential_min_max 42 1000000   -> Min: 3889, Max: 2147476004
$ ./parallel_min_max --seed 42 --array_size 1000000 --pnum 4 --by_files
                                     -> Min: 3889, Max: 2147476004  (совпадает)
$ ./parallel_min_max --seed 42 --array_size 1000000 --pnum 4        (pipe)
                                     -> тот же max; min может отличаться — см. замечание
$ make && ls sequential_min_max parallel_min_max exec_seq           (все собраны)
$ ./exec_seq                        -> ребёнок отработал sequential_min_max, exit 0
```

**Замечание (важно для понимания fork):** в pipe-варианте дети создаются после `srand(seed)` и наследуют одно и то же состояние генератора, поэтому куски массива у детей перекрываются одинаковыми последовательностями. В варианте `--by_files` в курсе используется reseeding в каждом ребёнке — отсюда расхождение min между двумя режимами при одном seed. Это не ошибка обмена данными, а особенность наследования состояния процесса при fork.

## Вывод
Освоены модели многопроцессности POSIX: `fork` + COW, синхронизация через `wait`, два способа межпроцессного взаимодействия (файлы и анонимные каналы), замещение образа процесса (`execvp`) и сборка проекта утилитой `make`.
