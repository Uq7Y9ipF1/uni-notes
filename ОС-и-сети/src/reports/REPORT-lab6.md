# Отчёт: Лабораторная работа №6 — Сетевое программирование: сокеты, клиент-сервер (TCP)

## ТЗ (что нужно было сделать по сути)
1. Реализовать **сервер** (`server.c`): принимает TCP-соединения на порту `--port`, читает запрос «k mod tnum», считает параллельно факториал по модулю в `tnum` потоков и возвращает uint64-ответ.
2. Реализовать **клиента** (`client.c`): читает из файла список серверов вида `ip:port`, рассылает запрос всем серверам **параллельно** (поток на сервер), объединяет результаты под мьютексом и печатает `answer:`.
3. Общие функции (`MultModulo`, парсинг uint64) вынести в библиотеку `common.c/common.h` → `libcommon.a`.

## Что нужно знать

### Архитектурный уровень
- **Сокет** — абстракция ядра «конечная точка коммуникации» (эндпоинт), описывается тройкой (семейство адресов, тип, протокол). AF_INET + SOCK_STREAM = TCP, SOCK_DGRAM = UDP. Сокет — обычный файловый дескриптор: read/write/close работают как с файлом, но байты уходят в сетевой стек.
- **Жизненный цикл TCP-сервера:** `socket()` → `bind()` (привязка к ip:port; INADDR_ANY = все интерфейсы) → `listen()` (переключение в passive mode, очередь backlog) → `accept()` (блокируется до SYN, создаёт **новый сокет** для соединения; listen-сокет остаётся для следующих). 4-way handshake завершается до возврата accept.
- **Клиент:** `socket()` → `connect()` (SYN; блокируется до установки соединения или ошибки) → write/read → close.
- **Порядок байт (endianness):** x86 — little-endian, сетевые протоколы — big-endian («network byte order»). Для чисел нужны `htonl/htons/ntohl`; у нас осознанно передаётся POD `uint64` после приведения, поэтому важно одинаковое представление на клиенте и сервере.
- **Байтовый поток vs сообщения:** TCP не сохраняет границы записей — сколько байт запрос, надо читать ровно N байт (цикл recv до полного), иначе «склейка» пакетов даст мусор.
- **Параллелизм на сервере:** модель «поток на соединение» или пул; здесь — потоки внутри одного запроса (разрезание диапазона [2..k] на tnum частей, произведение по модулю под мьютексом при слиянии).
- **Параллелизм на клиенте:** I/O-bound задача (ожидание ответа сети) — идеальный случай для pthread: поток на каждый сервер, общий аккумулятор защищён мьютексом; join всех, затем печать.
- **Разделение логики в библиотеку** (задание 3) убирает дублирование между client/server/lab5 — та же механика .a из лабы 2.

### Прикладной уровень
- Ошибки сокетов обязательны к проверке: bind может упасть с EADDRINUSE (порт занят), connect — с ECONNREFUSED (сервер не слушает).
- Заголовок `<arpa/inet.h>` даёт inet_pton/inet_ntop для строковых IP; `gethostbyname` — легаси-вариант.
- Структура `sockaddr_in {sin_family, sin_port (network order!), sin_addr}`; приводится к `struct sockaddr*`.
- Файл серверов: одна строка `ip:port`; разбор через strchr(':').

## Реализация
- `lab6/src/common.c/h` — `MultModulo(a,b,mod)` без переполнения (база+двойной сдвиг/модульная арифметика) и `ConvertStringToUI64`; сборка в `libcommon.a`.
- `lab6/src/server.c` — getopt `--port --tnum` с валидацией; socket/bind/listen/accept в цикле; на каждое соединение: чтение 3×uint64 (k, mod, tnum), запуск tnum pthread'ов на диапазон множителей, слияние произведений под mutex, отправка uint64-ответа; повторный accept (сервер обслуживает много клиентов).
- `lab6/src/client.c` — аргументы `--file servers.txt k mod`; чтение списка `ip:port`; для каждого сервера создаётся поток: connect → send запрос → recv ответ → lock → домножить общий результат → unlock; после join всех — печать `answer:` (произведение ответов всех серверов по модулю).
- `lab6/src/makefile` — цели `all: server client libcommon.a`, линковка `-L. -lcommon -lpthread`.

## Команды
```bash
cd lab6/src
make
# два сервера локально:
./server --port=20001 --tnum=4 &
./server --port=20002 --tnum=4 &
printf "127.0.0.1:20001\n127.0.0.1:20002\n" > servers.txt
./client --file=servers.txt 13 1000000007
# ожидаем answer == 13! % 1e9+7 = 227020758 (эталон Python)
kill %1 %2
```

## Проверка
E2E-прогон с двумя серверами (порты 20001/20002) и `k=13, mod=1e9+7`: клиент вернул значение, совпадающее с `math.factorial(13)%1000000007 = 227020758`. Отдельные проверки ошибок: неверный порт (EADDRINUSE), недоступный сервер (ECONNREFUSED) корректно сообщаются.
