# Отчёт: Лабораторная работа №3 — Процессы: fork, pipe, Makefile, exec

## ТЗ (что нужно было сделать по сути)
1. Реализовать `GetMinMax(array, begin, end)` — min/max на отрезке массива.
2. Написать `parallel_min_max.c`: разбить массив между N дочерними процессами (`fork`), собрать результаты **через временные файлы** (`--by_files`).
3. Тот же сбор результатов **через pipe** (вариант по умолчанию).
4. Настроить `makefile`: таргет `all`, зависимости объектных файлов, `clean`.
5. Написать программу, запускающую `sequential_min_max` через семейство `exec` из дочернего процесса.

## Что нужно знать

### Архитектурный уровень
- **`fork()`** создаёт новый процесс — копию родителя (адресное пространство копируется с copy-on-write). Возврат: `0` ребёнку, PID ребёнка родителю, `-1` при ошибке. Ключевое следствие: **память процессов изолирована** — результат вычисления ребёнка родитель «из воздуха» не увидит, нужен канал обмена (файл или pipe).
- **Синхронизация родитель↔ребёнок:** `wait()/waitpid()` блокируются до завершения ребёнка и забирают его статус (без этого ребёнок станет зомби). Ожидание обязательно **до** чтения результатов — иначе гонка.
- **`pipe(fd)`** — системный вызов, дающий кольцевой буфер ядра (~64 КБ): `fd[0]` — чтение, `fd[1]` — запись. Дескрипторы наследуются при `fork`, поэтому классическая схема: ребёнок закрывает `fd[0]` и пишет в `fd[1]`, родитель закрывает `fd[1]` и читает из `fd[0]`. Если родитель не закроет свою копию конца записи, `read` никогда не получит EOF и зависнет. По pipe передают только байтовые блоки (POD-структуры вроде `struct MinMax`) — указатели между процессами бессмысленны.
- **Файлы как IPC:** просто, но требует синхронизации (сначала `wait`, потом `fopen/fscanf`), имён и удаления мусора. Pipe — без дисковой записи, упорядочено, но однонаправленно.
- **Makefile** — инструмент инкрементальной сборки: цель = файл, зависимости сравниваются по mtime; пересобирается только устаревшее. Рецепты печатаются **табуляцией**, не пробелами. Переменные `CC`, `CFLAGS`; `.o` компилируются один раз (`-c`) и линкуются в несколько exe.
- **`execve`-семейство** заменяет образ текущего процесса (код/данные/стек) новой программой, **PID сохраняется**. После успешного exec код предыдущей программы больше не выполняется — поэтому вызов идёт в ребёнке после fork, а ошибки ловятся кодом сразу после execvp. `execvp` ищет файл по `PATH` и принимает массив аргументов, терминированный `NULL`.

### Прикладной уровень
- `getopt_long` — разбор длинных опций (`--seed=`, `--array_size=`, `--pnum=`, `--by_files`).
- Структура `MinMax {int min; int max;}` возвращается по значению — безопасно (копируется на стек).
- Инициализация поиска `INT_MAX`/`INT_MIN` (`<limits.h>`) снимает спецслучай первого элемента.
- Замер времени — `gettimeofday` до форков и после сбора результатов.

## Реализация
- `lab3/src/find_min_max.c` — цикл по полуоткрытому отрезку `[begin, end)`, два сравнения на элемент.
- `lab3/src/parallel_min_max.c` — разбор опций → генерация массива → создание ресурсов (файлы или pipe) → цикл `fork`: ребёнок считает свой чанк (последний берёт «остаток» до array_size) и пишет результат в `tmp_N.txt` или pipe; родитель считает активных детей, ждёт их всех через `wait`, затем собирает N частных пар min/max и агрегирует (min из mins, max из maxs — операция ассоциативна). В pipe-варианте родитель закрывает концы записи до чтения, дети — концы чтения сразу после fork.
- `lab3/src/makefile` — цели `all`, `sequential_min_max`, `parallel_min_max`, `exec_seq`, объектные `utils.o`/`find_min_max.o`, `clean`.
- `lab3/src/exec_seq.c` — `fork`; в ребёнке `execvp("./sequential_min_max", {"./sequential_min_max","42","100000",NULL})`; родитель `waitpid` + анализ `WIFEXITED/WEXITSTATUS`.

## Команды
```bash
cd lab3/src
make                      # соберёт всё (all)
make clean                # удалить .o, бинарники, tmp_*.txt

# Задание 1: последовательный вариант (для сверки)
./sequential_min_max 42 100000

# Задание 2: параллельно через файлы
./parallel_min_max --seed=42 --array_size=100000 --pnum=4 --by_files

# Задание 3: параллельно через pipe
./parallel_min_max --seed=42 --array_size=100000 --pnum=4

# Задание 5: fork + exec
./exec_seq
```

## Проверка
- `sequential` и `--by_files` дают идентичный корректный результат при одном seed (min/max совпадают).
- Pipe-вариант тоже возвращает корректную пару для своего массива; исторически min мог отличаться от by_files, т.к. дети при fork наследуют состояние генератора `rand()` — исправлено перевызовом `srand(seed)` в каждом ребёнке (детерминированность восстановлена).
- `make` пересобирает только изменённое; `clean` убирает артефакты.
- `exec_seq` печатает вывод `sequential_min_max` из заменённого процесса и статус завершения.

## Вывод
Освоены модели создания процессов (fork/COW), межпроцессного взаимодействия (файлы vs pipe, правила закрытия дескрипторов), ожидания завершения (wait/waitpid против зомби), замены образа (exec-семейство) и инкрементальной сборки (make).
