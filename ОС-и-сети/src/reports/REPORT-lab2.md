# Отчёт: Лабораторная работа №2 — Язык C, указатели, библиотеки

## ТЗ (что нужно было сделать по сути)
1. Реализовать `Swap(char*, char*)` — обмен двух символов через указатели.
2. Реализовать `RevertString(char*)` — переворот строки; разобраться, что делает `main.c`.
3. Собрать **статическую** (`librevstr.a`) и **динамическую** (`librevstr.so`) библиотеки из `revert_string.c`, слинковать с ними `main.c`, сравнить.
4. Написать юнит-тесты на CUnit и прогнать их, слинковав с динамической библиотекой.

## Что нужно знать

### Архитектурный уровень
- **Параметры функции в C передаются по значению.** Чтобы изменить переменную вызывающего кода, передают её адрес (`&ch`), а функция работает через разыменование `*left`. В памяти это две ячейки + указатель на одну из них; обмен требует временной переменной.
- **Строка в C — массив char со `\0` на конце.** Переворот in-place = обмен симметричных пар `str[i] ↔ str[len-1-i]` за len/2 шагов; никаких новых аллокаций не нужно.
- **Стек vs куча.** Стек: автоматическое выделение/освобождение кадрами, быстрый, ограниченный (≈8 МБ), размер известен на этапе компиляции. Куча (`malloc/free`): ручное управление, размер выбирается в рантайме, живёт до явного `free`; забытый `free` = утечка, двойной `free`/use-after-free = неопределённое поведение.
- **Статическая библиотека (.a)** — архив объектных файлов (`ar rcs`). Линковщик копирует нужные объекты прямо в исполняемый файл: бинарник самодостаточен, но больше; обновление библиотеки требует **пересборки приложения**.
- **Динамическая библиотека (.so)** — отдельный ELF, который динамический загрузчик (`ld-linux.so`) отображает в адресное пространство процесса при запуске. Код обязан быть позиционно-независимым (`-fPIC`), сборка — `-shared`. Поиск: `LD_LIBRARY_PATH` → `/etc/ld.so.cache` (`ldconfig`) → стандартные пути. Обновление `.so` меняет поведение **уже скомпилированных** программ без пересборки — в этом ключевая разница с `.a`.
- **CUnit** — фреймворк юнит-тестирования: `CU_ASSERT_STRING_EQUAL` и т.п., базовый режим печатает список passed/failed тестов.

### Прикладной уровень (опции gcc)
| Флаг | Значение |
|---|---|
| `-c` | компилировать без линковки → `.o` |
| `-o имя` | имя выходного файла |
| `-I путь` | где искать `#include`-заголовки |
| `-L путь` | где искать библиотеки при линковке |
| `-lrevstr` | слинковать с `librevstr.so`/`.a` |
| `-l:librevstr.a` | явно взять статический архив (иначе приоритет у .so) |
| `-fPIC` | позиционно-независимый код (для .so) |
| `-shared` | собрать разделяемую библиотеку |

## Реализация
- `lab2/src/swap/swap.c` — обмен через temp-переменную и разыменование указателей.
- `lab2/src/revert_string/revert_string.c` — цикл `for (i < len/2)` с обменом симметричных символов + проверка `if (!str)`.
  **Как работает main.c:** проверяет ровно 1 аргумент → `malloc(strlen+1)` в куче → `strcpy` копии → `RevertString` переворачивает in-place → печать → `free`.
- Библиотеки собраны командами ниже; `static_app` и `dynamic_app` слинкованы с `.a` и `.so` соответственно.
- `lab2/src/tests/tests.c` — 4 ассерта CUnit (обычная строка, палиндром, пустая строка, одна буква).

## Команды
```bash
cd lab2/src

# Задание 1: swap
cd swap && gcc main.c swap.c -o swap_app && ./swap_app      # -> b a

# Задание 2: revert (прямая компиляция)
cd ../revert_string
gcc main.c revert_string.c -o revert_app && ./revert_app "Hello"   # -> olleH

# Задание 3: статическая библиотека
gcc -c revert_string.c -o revert_string.o
ar rcs librevstr.a revert_string.o
gcc main.c -L. -l:librevstr.a -o static_app
./static_app "Hello"                     # работает без внешних зависимостей

# Задание 3: динамическая библиотека
gcc -c -fPIC revert_string.c -o revert_string_pic.o
gcc -shared revert_string_pic.o -o librevstr.so
gcc main.c -L. -lrevstr -o dynamic_app
export LD_LIBRARY_PATH=.:$LD_LIBRARY_PATH
./dynamic_app "World"                    # -> dlroW

# Задание 4: CUnit-тесты
sudo apt -y install libcunit1 libcunit1-dev
cd ../tests
gcc tests.c -I../revert_string -L../revert_string -lrevstr -lcunit -o tests_app
export LD_LIBRARY_PATH=../revert_string:$LD_LIBRARY_PATH
./tests_app                              # все 4 теста passed
```

## Ответы на вопросы ТЗ
- **Зачем указатели в Swap?** Без них функция получила бы копии символов и изменения исчезли бы при выходе.
- **Где viveт строка после malloc?** В куче, пока не вызван `free`; стек-копия умерла бы вместе с кадром main.
- **Чем .a отличается от .so?** .a вшивается в exe (самодостаточность, большой размер, пересборка при изменении); .so подгружается при старте (экономия места, общее обновление для всех клиентов, зависимость от наличия файла и путей поиска).
- **Демонстрация «живой» замены .so:** изменили исходник (баг `i+=2` в цикле) → пересобрали только `.so` → ранее собранные `dynamic_app`/`tests_app` сразу подхватили новое поведение (тесты упали), без перелинковки. Со `static_app` так нельзя — он несёт старый код в себе.
