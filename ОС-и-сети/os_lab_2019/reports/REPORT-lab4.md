# Отчёт: Лабораторная работа №4 — Процессы: таймауты, зомби, память процесса

## ТЗ (что нужно было сделать по сути)
1. В программу параллельного поиска min/max из лабы 3 добавить необязательный параметр `--timeout N`: если дочерние процессы не завершаются за N секунд — убить их. Разобраться с неблокирующим ожиданием и сигналами.
2. Создать процесс-зомби и объяснить, чем он опасен и как от него избавиться.
3. Изучить сегменты памяти процесса по программе `process_memory.c` (`etext`, `edata`, `end`).
4. Всё собрать makefile'ом.
5–6. Написать параллельную сумму массива с помощью **потоков** (pthread), функцию суммирования вынести в отдельную статическую библиотеку.

## Как реализовано

### Задание 1 — parallel_min_max.c с --timeout
К копии программы из лабы 3 добавлен parsing `--timeout` (в секундах). Вместо блокирующего `wait()` родитель крутит цикл:
```c
pid_t r = waitpid(child_pid, &status, WNOHANG);  // неблокирующее ожидание
if (r == 0) {                                    // ребёнок ещё жив
    if (истекло timeout) kill(child_pid, SIGKILL);
    usleep(10 * 1000);                           // 10 мс пауза, чтобы не жечь CPU
}
```
После `SIGKILL` ребёнок всё равно обязательно дожидается через `waitpid` — иначе вместо зависшего процесса получился бы зомби. Таймер — по разнице `timeval` до/после.

**Проверка:** обычный запуск даёт корректный результат; тест с массивом 200 000 000 элементов и `--timeout 2` — дети убиты вовремя, программа завершилась примерно за 2 секунды без зависания.

### Задание 2 — zombie.c
```c
pid_t pid = fork();
if (pid == 0) { return 0; }          // ребёнок сразу завершается -> становится зомби
else { sleep(30); }                  // родитель НЕ вызывает wait()
```
Пока родитель спит, `ps -o pid,stat,comm` показывает ребёнка со статусом **`Z`** (defunct). Проверено фактическим запуском.

Что такое зомби: процесс уже завершился, его ресурсы (память, дескрипторы) освобождены ядром, но в таблице процессов остаётся запись с кодом выхода — она нужна родителю для `wait()`. Опасность: при массовом появлении зомби исчерпывается лимит PID (`kernel.pid_max`) и новых процессов создать нельзя. Способы борьбы: (1) дождаться через `wait/waitpid`; (2) `signal(SIGCHLD, SIG_IGN)` — ядро само убирает детей; (3) двойной fork — сирота переприходится init/systemd, который подождёт.

### Задание 3 — process_memory.c
Скомпилирован и запущен. Вывод объясняется так:
- `etext` — адрес конца **текстового сегмента** (код программы);
- `edata` — конец сегмента **инициализированных данных** (.data);
- `end` — конец сегмента **неинициализированных данных** (.bss), т.е. начало кучи; между `edata` и `end` — «дыра» BSS.
Выше — стеки и mmap-области, ниже адреса растут при `brk/malloc`.

### Задания 5–6 — parallel_sum.c + libsum.a
- аргументы `--threads_num --seed --array_size`; генерация массива переиспользована из лабы 3 (`GenerateArray`) и выполняется **до** старта таймера;
- диапазон режется на N кусков, каждый поток считает частичную сумму, результаты складываются после `pthread_join`;
- функция `Sum` вынесена в `sum.c/sum.h` → архив `libsum.a` (`ar rcs`), к нему прилинкован `parallel_sum` (задание 6 — библиотека).

**Проверка:** сумма совпала с последовательным эталоном (1083572212 при seed=42, n=10⁶), время ~2.5 мс; makefile собирает все цели (`make` → parallel_min_max, process_memory, zombie, psum).
